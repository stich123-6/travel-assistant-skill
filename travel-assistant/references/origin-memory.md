# 常用／默认出发地点记忆

这里的“默认出发地点”是记住的候选地点，可有多条；仍遵守未指定本次出发地先问用户的约定。地点资料保存到当前用户的持久配置，不写入Skill包，也不写入宿主模型的全局记忆。

## 意图与必要输入

| 用户表达 | 行为 |
| --- | --- |
| “增加默认出发地点” | 打开新增输入框，收集具体位置；名称可选 |
| “增加默认出发地点，杭州东站” | 名称可用“杭州东站”，位置已给出，直接保存；不再问同一问题 |
| “记住公司地址：杭州市……路……号” | 没有公司条目则新增；已有且明确是更新指令则修改该条目 |
| “修改公司出发点” | 唯一匹配后打开预填输入框，收集新名称或新地址 |
| “把公司地址改成杭州市……路……号” | 唯一匹配后直接修改，不生成第二条公司记录 |
| “删除默认出发地点公司” | 唯一匹配后删除并刷新卡片，用户这一指令就是删除该记忆的授权 |
| “查看默认出发地点” | 读取当前用户最新列表，展示管理卡片 |

“家”“公司”“客户办公室”等只有别名、没有实际位置时，仍缺具体地址；不能用历史路线、IP或另一个人的资料补成地址。已给出的地点文本可以先记住，路线查询时再用腾讯地图解析；当场查询存在多个候选时交给用户选，不把第一个结果悄悄覆盖原文。

未明确条目或名称匹配多个条目时，展示最新列表让用户选，不猜修改/删除对象。用户取消输入或提交空值时不保存。只有名称缺失而地点已给出时，从地点名称生成标签即可。

新增遇到同名同址返回已有条目；同名不同址不覆盖，展示“修改原地点／换个名称新增”选项。用户已明确要求修改且条目唯一时，不再重复确认。

## 本地脚本

使用随包`scripts/origin_memory.py`，只依赖Python标准库。优先使用WorkBuddy已有Python运行时；不可用时说明持久记忆尚不能执行，不私自安装、不仅凭对话声称保存成功。

**从选定工作空间运行，脚本路径使用实际Skill目录的绝对路径，`--data-dir`明确指向该工作空间的`.travel-assistant`。** 不要切换到Skill目录后把用户资料写进去。

团队共享项目中，`--data-dir`改用宿主确认归属当前成员的私有持久存储位置，不能默认采用共享资产目录。用户ID哈希只分开记录，不替代存储权限；没有私有目录时按[团队项目约定](team-project.md)暂停持久记忆，仍可继续本次规划。

所有命令都需要`--user-id`，值必须来自宿主可信的当前用户身份；不能从普通消息自行猜测，也不能让用户输入别人的ID切换资料。可用的个人独立工作空间标识也须由宿主确认归属。不具备稳定用户标识或持久目录时，说明记忆不可持久化，不读取可能属于他人的配置。

命令形态如下，`SCRIPT`、`DATA_DIR`、`USER_ID`和`ORIGIN_ID`表示运行时真实参数；通过结构化工具或安全参数数组传入，不能拼接用户文本为shell代码：

```text
python -X utf8 SCRIPT --data-dir DATA_DIR --user-id USER_ID list
python -X utf8 SCRIPT --data-dir DATA_DIR --user-id USER_ID add
python -X utf8 SCRIPT --data-dir DATA_DIR --user-id USER_ID add --label 公司 --address 具体位置 --expected-revision 0
python -X utf8 SCRIPT --data-dir DATA_DIR --user-id USER_ID update --origin-id ORIGIN_ID --address 新地址 --expected-revision 1
python -X utf8 SCRIPT --data-dir DATA_DIR --user-id USER_ID delete --origin-id ORIGIN_ID --expected-revision 2
```

新增只给出地址时可省略`--label`，脚本以该地点为名称。修改支持`--label`、`--address`任意一项或两项；ID保留。版本号来自刚读取的列表或用户提交的卡片，不使用示例数字。

## 返回与卡片更新

- `needs_input`：用`form`内容打开输入框；已有名称预填，等待用户输入地址。此时没有保存。
- `saved`、`deleted`：写入并回读核对成功；使用返回的`card`更新出发地选择卡，并显示新名称/地址或删除结果。
- `unchanged`：重复添加同址或内容没有变化；返回现有条目和最新卡片，不重复新增。
- `listed`：列表查询结果。每次展示出发地卡都从这里读，不使用对话中缓存的旧卡片。
- `error`或非零退出码：按`code`处理。`duplicate_label`让用户选择修改或改名；`stale_revision`、`not_found`重新读列表；保存失败不显示成功；`memory_busy`稍后刷新，不强行覆盖另一个写入。

返回的`card.revision`用于识别旧卡片；`options`包含真实地点ID、显示名称、地址和操作类型，`selected_id`保持空，不能自动替用户选择。卡片回调应同时核对当前用户、最新列表版本和地点ID。

宿主支持更新现有卡片时，按真实工具schema更新原卡；不支持原位更新就发一张最新卡并告知旧卡失效。没有原生交互工具时，用相同数据生成编号选项，输入框降级为短文本提问；不承诺Skill能凭空新增原生弹窗。

## 历史行程与旧配置

本次行程引用记忆时记录地点ID与当时确认的地址快照。修改或删除常用地点只改变后续候选，不偷偷改写已批准的行程、日程、订单；用户明确要求同时改本次行程时，再更新方案并重算受影响路线。

旧版工作空间可能有`.travel-assistant/profile.json`及`places.home/company`。只有宿主能确认归属当前用户时才迁移：保留原文件和非地点配置，在用户新配置中保留有效的时区、日历等设置，将旧地址逐条用新增流程导入。无法确认归属则不自动导入。不要把旧`places`与新列表长期当成两个同时生效的地址来源。

脚本用独立写锁和临时文件替换保护保存；异常中断可能留下锁文件。仅在确认原写进程已经结束后处理残留锁，不通过不断删除锁强行写入。多设备或不同工作空间之间没有配置同步接入时，不能承诺记忆已同步。
