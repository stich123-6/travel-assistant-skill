# 出行服务 MCP 连接器运行约定

本版保留行程助手 Skill，以腾讯地图、同程和滴滴的 MCP 连接器提供出行工具。钉钉仍按原接入规则处理，手机系统日历仍待接入。本版没有把行程助手本身部署成独立 MCP Server。

## 每次新任务

1. 从宿主取得当前任务可用的连接器及工具信息；结合实际返回确认服务提供方和用途，不能仅按工具同名判断来源。记录非秘密的连接器ID、提供方、执行端、检查时间及所需能力。
2. 已授权但未在当前任务启用时，提供宿主实际存在的启用入口。未授权或授权过期时，引导连接器自己的授权流程，不要求用户在聊天中重复发送 Key。
3. 使用当前实际工具列表/schema发现能力。工具可用时无需供应商 Skill、本地 OpenClaw、mcporter、Python 地图包或同程脚本。地址记忆脚本自身的 Python 要求不受此调整影响。
4. 通过工具发现或本次需要的只读调用确认连通性。仅出现在列表里不等于认证成功；历史“已连接”也不能证明当前执行端可调用。不要为验证连接叫车、取消订单或发消息。
5. 未提供连接器/工具时标记 `waiting_connector`；明确未授权时标记 `waiting_authorization`；网络或参数错误按真实错误说明，不能一律说缺 Token。只暂停受影响的子任务，继续可完成的活动信息整理与准备清单，不编造实时价格、路线耗时或余票。

本次只按需检查服务：本市路线通常只需要地图，不提前要求连接同程和滴滴。用户未明确出发地仍先问；参展时仍先确认展会名称再搜索。

## 凭证与跨任务复用

- 服务凭证由宿主真实支持的本人连接器授权机制管理；本 Skill 不接收、保存、迁移或回显 Key，不从旧聊天提取它们，也不写入 `.env`、地点记忆、共享项目、安装包或 GitHub。
- 新任务按宿主已有授权重新选择/启用连接器。当前任务找不到授权时，先检查账号、执行端、连接器ID和启用情况；不能断言“新建任务删除了 Key”，也不能声称已自动恢复。
- 一次授权、多个新任务复用必须在目标云端实测成立。本机授权、共享项目配置或一次调用成功不构成跨任务验证。
- WorkBuddy 官方自填 Token 模式凭证仅存本机，不经过云端；不能承诺该模式自动满足手机纯云端使用。只有平台实际提供的本人云端授权可用时才报告云端已接通。没有相关入口时交管理员/平台接入，不通过共享管理员 Key 绕过。
- 用户主动发送 Key 时，不回显、不把它写进任务文件或长期记忆；引导到真实的私有凭证入口。普通文字卡片不能伪装成密码表单。

## 最小验收

在目标云端任务A启用本人连接器，发现工具并完成一次公开地点只读查询；随后新建任务B，不发送 Key，确认能重新启用同一本人连接器并完成同样的只读查询。任务B失败时区分授权、未启用和环境问题，不把任务A的成功复制为任务B的成功。

官方依据：[WorkBuddy 连接器规范](https://open.workbuddy.cn/docs/connector)、[腾讯位置服务 MCP](https://lbs.qq.com/service/MCPServer/MCPServerGuide/overview)、[滴滴 MCP](https://mcp.didichuxing.com/api)。本文件是运行约定，尚未完成上述真实云端验收。
